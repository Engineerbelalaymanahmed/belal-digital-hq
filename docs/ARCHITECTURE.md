# Architecture (Phase 0 summary and migration paths)

**Stack:** static HTML + CSS + vanilla ES modules, no build step, no dependencies. Chosen for GitHub Pages compatibility, near-zero JavaScript, nothing to patch, and ease of migration. Rejected: Next.js (server features unused on Pages), React+Vite (build chain and dependency surface for a content-driven site). Revisit when an admin area or CMS preview is needed.

**Separation:** content = `data/*.json`; presentation = `assets/css`; logic = `assets/js/app.js` (helpers, one renderer per page); assets = `assets/*`; config = `data/site.json`; routing = one folder per page, generated by `scripts/generate-pages.sh` from `scripts/template.html` (clean URLs, per-page title/description/canonical, static h1 fallback for crawlers).

**Data layer:** the UI only calls `get(name)`. Setting `apiBase` in `data/site.json` makes it request `{apiBase}/{name}` instead of `data/{name}.json`. A CMS or API must return the same JSON shapes.

**i18n:** every text field is `string` or `{en, ar}`; UI strings in `data/i18n.json`; `lang`/`dir` set on `<html>` and persisted. Not yet done: per-language URLs (`/ar/`) and hreflang.

**Security:** strict CSP in the template (self only, no inline script/style), DOM built with `textContent` (no innerHTML), URLs sanitised to http(s)/mailto/tel, external links `noopener noreferrer`, no secrets, no third-party scripts, no tracking.

**Migration**
- *Custom domain:* add it in Pages settings, add a `CNAME` file, run the generator with `SITE=https://your-domain/`.
- *Hosting/CDN:* upload the folder as-is to any static host (set cache headers for `assets/`).
- *CMS / admin:* expose the same JSON over an API, set `apiBase`, and add that origin to `connect-src` in the template. Forms: set `contactFormEndpoint`, add the origin to `connect-src` and `form-action`.
- *Analytics:* add a privacy-friendly script (Plausible/Umami) only after adding its origin to `script-src`/`connect-src`.
